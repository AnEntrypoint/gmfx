# gm native parity matrix

fx carries gm's functions and behaviour as native defaults of its own loop, tools and prompt. Nothing in fx imports, spawns, requires or vendors gm at run time. This matrix has one row per gm function or behaviour: what it is for, what fx has today, and the fx-native design for the gap. gm was read at /workspace/gm (HEAD db20be0), read-only. fx lines were read while other work was landing and may have moved by a few lines.

Legend for paths: `G/` is /workspace/gm/src/, `F/` is /workspace/fx/fx/src/.

## Top 10 by benefit

1. **V26-V31 output condensing** (ANSI strip, repeat folding, head/tail, signal lines). fx has nothing here, and every long build or test run pays for it. V30 matters most: fx's byte cut can drop the one failing line.
2. **V16 foreground wait**. fx returns a `running` snapshot after 30 s and caps foreground at 300 s, so any real build costs extra TaskOutput turns.
3. **V39 + V46 blocking wait and completion notice**. TaskOutput blocks 5 s at most, WaitFor is experimental, and nothing tells the model a task finished, so it polls.
4. **V54 ranked search**. Finding code from a description takes several grep rounds today; the BM25 scorer already exists in `capability_retrieval.zig`.
5. **V15 parallel calls in every mode, including independent writes**. Outside `auto`/`yolo`, each read is serial.
6. **V73/V74 callers and impact**. No symbol-level search exists, so call sites are found by grep and reading.
7. **V1/V2 whole-file read and exact next offset**. A 400-line default means two or more calls for most source files.
8. **V42 job adoption across restart**. A restart or resume kills every background build.
9. **V72 CI status**. After a push the model has no way to see the result except hand-written `gh` calls.
10. **V56/V57/V60 grep literal mode, fallback and hit-centred excerpts**. The schema says literal while the engine is regex, which causes silent misses and retries.
